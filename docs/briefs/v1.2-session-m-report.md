## The Task 1.2 finding, stated explicitly

**The reading view does mark error tool results.** `templates/_message.html` renders a
`tool_result` card with an `is-error` CSS class and appends the literal text ` · error` to
the card meta (`{{ N }} inner block(s) · error`). The export therefore mirrors it: the tool
card's result summary carries the same ` · error` marker
(`> **[Tool: bash_tool]** 1 inner block · error`). Verification was **code-level** — the
presentation rule lives entirely in the template, so no real export content needed to be
read (the census had already established the 86 error results as an aggregate).

## Interpretations and soft flags

No soft gate in the brief's strict sense was tripped (nothing needed fixing), but the
following are the judgment calls made inside the design's intent, flagged prominently:

1. **`project` frontmatter and the No-Project sentinel**: the design record's condition is
   "only when the conversation is tagged to a project". The sentinel is deliberately *not* a
   project (Session B), so a sentinel-tagged conversation exports **without** the field. The
   alternative — `project: "No Project"` — would have preserved the triage distinction
   between "reviewed, no project" and "not reviewed"; if that record matters in exports,
   Session N (or later) can revisit.
2. **Orphan tags** (project uuid no longer in the archive): there is no label to resolve, so
   the field is absent.
3. **Inspect mode**: the field is always absent while inspecting — tags are primary-export
   state and never pair with an inspected export's conversations (Session K). Test-pinned,
   including the sharp case where the inspected archive contains the *same* conversation
   uuid as a tagged primary conversation.
4. **Conditional-field scoping**: `thinking`/`attachments`/`branch_points` trigger on what
   the *conversation* has, across all branches — the design record's literal wording
   ("when the conversation has"), and consistent with its honesty rationale. Only
   `messages` is path-scoped, and the spec says so explicitly.
5. **`response(s)` in the branch annotation** is treated as literal spec text (the brief
   demands the design record's literal strings), so `1 alternate response(s) exist` is what
   ships. Flagged as candidate copy polish for Session N — on both surfaces if changed.
6. **The files notice wording**: the design record specifies "the one-line notice" without a
   literal string, so the export mirrors the reading view's wording under the labelled-
   blockquote rule: `> **[Files]** N binary file(s) attached (not included in export):
   name1, name2` (pluralisation mirrors the template's).
7. **Unknown-block `<type>`**: the placeholder uses the object's raw `type` attribute when
   present, else the class name. This path is **dormant by construction**: the parser
   currently *drops* unknown raw block types (warn-only) before they reach the model, so the
   placeholder can only fire on directly constructed objects. Observation recorded (not
   fixed — a parser change is outside this brief): CLAUDE.md's preserve-and-flag list cites
   unknown content-block types as an existing example, but the parser's actual behaviour is
   drop-and-warn; preserving them would make both the reading view's and the export's
   placeholder paths reachable.
8. **Orphan `tool_result`** (a result with no preceding call): rendered as its own card via
   the design record's rule (which names both block types). None exist in real data —
   dormant, unit-pinned.
9. **Collision fragment** is the *last* eight uuid characters: the synthetic fixtures share
   their leading `00000000`, and real uuids are unique at either end. A same-fragment
   collision falls back to the full uuid (defensive; unreachable in practice).
10. **`generator` version** reads `pyproject.toml` via `tomllib` (currently `1.1.5`;
    Session N's bump will flow through automatically). Installed-package metadata is only
    the fallback — the dev venv's editable-install metadata is frozen at `1.1.0`, which is
    why it can't be the primary source.
11. **Filename dates** are the conversation's created date **as stored (UTC)** — the same
    instant the frontmatter `created` field carries, so file and filename never disagree
    (a local-date filename would also make tests timezone-dependent). `exported` and the
    zip name use the export-day local date.
12. **Mechanical choices**: empty bulk selection → 400; duplicate posted uuids are
    de-duplicated; empty text blocks contribute nothing (verbatim of nothing); option flags
    accept `1/true/yes/on` (case-insensitive), anything else is off, absent/empty takes the
    default.

## Operator note — URLs worth hitting by hand (no UI yet)

With the app running (`run.ps1`), against your own export:

- **Single, defaults** (thinking omitted, attachments included):
  `http://127.0.0.1:5000/conversations/<uuid>/export`
- **With thinking**: `http://127.0.0.1:5000/conversations/<uuid>/export?thinking=1`
- **Attachment references only**: `.../export?attachments=0`
- **A branch combination**: switch branches on the detail page, then copy its query string
  onto the export URL — e.g. `.../export?branch=<message-uuid>&thinking=1`.
- **Bulk POST** (CSRF makes a raw curl awkward; the test client is the quickest scratch
  form). From the project root, paste into PowerShell — it boots the app in-process against
  your stored export (normal startup semantics) and drops the zip in the current directory.
  Mechanics verified in-session against the synthetic fixture (200, spec-named zip, correct
  members):

  ```powershell
  @'
  import re
  from app import create_app

  client = create_app().test_client()
  page = client.get("/inspect").get_data(as_text=True)
  token = re.search(r'name="csrf_token" value="([^"]+)"', page).group(1)
  resp = client.post(
      "/conversations/export",
      data={"csrf_token": token, "conversation_uuid": ["<uuid-1>", "<uuid-2>"]},
  )
  name = resp.headers["Content-Disposition"].split('"')[1]
  open(name, "wb").write(resp.data)
  print(resp.status_code, name)
  '@ | .venv\Scripts\python.exe -
  ```

- **While inspecting**: open `http://127.0.0.1:5000/inspect`, load another archive, then hit
  any `/conversations/<uuid>/export` URL for one of *its* conversations — the file should
  carry the inspected content and no `project` field.
