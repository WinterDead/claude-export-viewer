# v1.2 — Session M Brief: conversation-export serializer + download endpoints

Read CLAUDE.md, `docs/plan.md`, and **`docs/export-design.md`** — the design record is the
normative format specification for this session; this brief adds the endpoint mechanics, the
census-driven edge cases, and the test targets. Also read the census
(`docs/content-block-census.md`) — two of its observations are tasks here.

## Scope

Backend only: the serialisation module and the two download endpoints, fully tested at the
HTTP level. **No UI** — no buttons, no checkboxes, no action-bar changes, no template edits
beyond nothing (Session N owns the UI, print polish, and the README/help updates). There are
no open design decisions in this brief: the census returned an empty unmapped-type list, so
every rendering situation is covered by the design record plus the additions below. A
rendering situation covered by neither is a **hard stop**.

## Gate vocabulary

- **Soft gate** — resolve it if the fix is obvious and within the design's intent, and flag
  it prominently in the report.
- **Hard stop** — end the session and report without implementing, even if the resolution
  seems obvious.

**Hard stops for this session, overriding everything below**: any rendering situation not
covered by the design record or this brief; any server-side file write originating from an
export request; any edit to README.md or `viewer/content/help.md`; any sanitiser or stack
change.

## Task 1 — serializer

A new module (suggested `viewer/export.py`) implementing the design record's format spec
exactly: frontmatter with its conditional fields, H1 title, sender headings via the existing
display-layer mapping (unknown senders pass through raw), verbatim body text, and the
labelled-blockquote forms for thinking, tools, attachments, files, artifacts, and unknown
blocks — all literal strings as written in the design record.

Census-driven additions (both from Session L, aggregate-verified against the real archive):

1. **Tool use with no result** (two exist in the real data): render the card as, byte-exact:

<!-- VERBATIM -->
> **[Tool: <name>]** — no result recorded.
<!-- END VERBATIM -->

2. **Error tool results** (86 exist): *verify* how the reading view presents an error result
   versus a normal one — this is a verification target, not a premise. Mirror whatever it
   does: if the reading view marks errors, carry the same marker into the card; if it makes
   no distinction, the export makes none either (parity), and note the symmetry in the
   report as a possible future enhancement for both surfaces.

Options plumbing: `include_thinking` (**default false**) and `include_attachment_text`
(**default true**), honoured exactly as the design record specifies, including the
`thinking: included | omitted` and `attachments: included | referenced` frontmatter fields'
conditional presence.

## Task 2 — endpoints

- **Single conversation**: GET, returning `text/markdown` with a Content-Disposition
  attachment filename per the naming spec (`YYYY-MM-DD_<slug>.md`, created date, synthesised
  preview slug for untitled). The endpoint accepts the **same branch parameters as the
  conversation detail page** and exports that displayed combination — WYSIWYG per the design
  record — with the branch-point annotation line at each branch point on the path. Options
  as query parameters with the defaults above.
- **Bulk**: POST (CSRF-protected like every other POST), taking the selection's conversation
  ids and the two options; returns `application/zip` named
  `claude-conversations_YYYY-MM-DD.zip`, flat, one `.md` per conversation on its **default
  branch path**, filename collisions resolved with a short uuid fragment. The zip is
  assembled for the response, never written server-side.
- **Inspect-mode compatibility** (the Session K forward note): both endpoints must work
  against an inspected export — that's a primary use case — and the no-trace rule must
  survive them.

## Tests (this list defines the target state)

1. Frontmatter: every field present and correct on a fully-featured fixture; conditional
   fields absent when their condition fails (`project` untagged, `branch_points` zero,
   `thinking`/`attachments` when the conversation has none).
2. Sender headings: `## User` / `## Assistant`; an unknown sender passes through raw.
3. Body fidelity: a fixture message containing its own `##` headings and fenced code blocks
   exports byte-identical inside the document.
4. Thinking: excluded by default with `thinking: omitted`; included with the flag; the
   truncated / cut-off label variants verified via **synthetic fixtures** (the census found
   zero flagged blocks in the real data — this path is fixture territory by necessity).
5. Tool cards: with result; with **no result** (authored form above); error-result handling
   matching the Task 1.2 verification outcome.
6. Attachments: full-text form; `— text not exported.` form when the toggle is off; the
   frontmatter field flipping between `included` and `referenced` accordingly.
7. Files note, artifact placeholder, unknown-block placeholder — one test each against
   fixtures.
8. Branches: a branching fixture exports the requested combination with correct annotation
   counts; the bulk path uses the default branch; a non-branching conversation gets no
   annotation and no `branch_points` field.
9. Naming: dated slug; untitled-conversation slug from the synthesised preview; bulk
   collision gets the uuid fragment; zip name matches the spec.
10. Bulk integrity: zip contents correspond exactly to the posted selection — nothing
    missing, nothing extra.
11. Options defaults pinned at both endpoints (thinking off, attachment text on).
12. No server-side writes: a `cache/` (and repo-tree) snapshot is unchanged across single
    and bulk exports.
13. Inspect mode: both endpoints export the **inspected** export's content while inspecting;
    the K no-trace snapshot test still passes with exports in the cycle.
14. Content types and Content-Disposition headers correct on both endpoints.
