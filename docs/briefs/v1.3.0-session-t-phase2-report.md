# Session T Phase 2 Report — dark mode

Brief: `docs/briefs/v1.3.0-session-t-brief.md`, Phase 2. Everything below implements
the chat-ratified design verbatim; the Session R Phase 2 theming lens was the work
list.

## What shipped

- **Default follows the system.** The server stamps exactly one of
  `theme-system` / `theme-light` / `theme-dark` on `<html>` from the `viewer_theme`
  cookie (absent or mangled → `system`), so the correct palette paints on first
  render — no flash, no localStorage. `color-scheme` is declared per theme
  (`light dark` under System) and the `theme-color` metas are server-rendered to
  match (a media-paired duo under System, a single value under an override).
- **The control** sits in the nav tail after Help, C4 copy exactly (label `Theme`,
  options `System`, `Light`, `Dark`), on the same select-submit idiom as the tag
  form (hidden csrf + next, `onchange` submit, noscript button). It posts to the new
  `/theme` route: value validated against the known three (unknown → 400), `next`
  guarded by the same open-redirect check the tag forms use, cookie set for a year
  (`SameSite=Lax`, `HttpOnly`). The route is deliberately not guarded by the
  inspect-mode refusal — theme is app chrome, not export or tag state. The control
  carries the stable `theme-control` class so capture-time suppression works exactly
  like the footer's.
- **Tokens, not per-element overrides.** The theming lens's census — 59 hardcoded
  colour declarations on the screen side — is now fully tokenised: 20 new custom
  properties beside the existing 7 (`--surface`, `--surface-muted`,
  `--surface-assistant`, `--on-accent`, `--on-accent-soft`, `--accent-bg`,
  `--shadow`, `--mark-bg`, `--error-accent`, `--error-bg`, and the four banner
  colourways: amber orphan via `--accent-bg`/`--accent`, and dedicated
  bg/border/fg triads for the red load-error, grey degraded, and blue inspect
  banners plus the inspect hover). Light values are byte-equal to the literals they
  replaced; a sweep check confirmed **zero** colour literals remain in screen rules.
  Two identical dark token sets are declared — `html.theme-dark`, and
  `html.theme-system` under `@media (prefers-color-scheme: dark)` — so the dark set
  applies under System only when the OS prefers dark. In dark, fills invert
  politely: `--on-accent` goes near-black so text sits readably on the bright
  accent/link/muted fills.
- **highlight.js**: `github-dark.min.css` vendored from the same 11.11.1
  cdn-release as the light theme (no CDN at runtime, ever); the vendor README
  records it and the BSD-3-Clause LICENSE already alongside covers both. Selection
  is server-rendered media-attribute routing — no JS: Light → light sheet
  unconditioned; Dark → light sheet `media="print"` + dark sheet `media="screen"`;
  System → light sheet `media="print, screen and (prefers-color-scheme: light)"` +
  dark sheet `media="screen and (prefers-color-scheme: dark)"`. Print therefore
  always highlights light. Both sheets stay ahead of `style.css` so app styles keep
  winning equal-specificity ties.
- **Print stays light**: an additive reset at the top of `@media print` restores
  every dark-varying token to its light value at theme-block specificity
  (source order wins the tie), plus `color-scheme: light`. PDF output is unaffected
  by the active theme.

## Driven-browser verification (Chromium 148, real dev server)

- Fresh state: `theme-system` class; the pane's browser prefers dark, and the page
  rendered the dark palette (`#16181b` body) purely via `prefers-color-scheme`.
- Switched to Light through the real control: redirect back to the same page,
  `theme-light` class, light palette (`#fefefe` body, `#ffffff` header surface);
  `document.cookie` empty — the HttpOnly flag doing its job.
- Switched to Dark: `theme-dark` class, dark palette (`#16181b`/`#e8e6e3`,
  `#1e2124` surfaces, `#7cb5f2` links), `color-scheme: dark`, stylesheet routing in
  the DOM exactly as designed (light sheet `media="print"`, dark sheet
  `media="screen"`).

  and highlight.js rendering with github-dark's colours (`#c9d1d9` base,
  `#a5d6ff` tokens) on a real highlighted code block.
- Control returned to System afterwards.
