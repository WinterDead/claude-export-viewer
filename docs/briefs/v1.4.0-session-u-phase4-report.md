# Session U Phase 4 Report — v1.4.0 model, loader, search

Brief: `docs/briefs/v1.4.0-session-u-brief.md` (phase 4). Record:
`docs/export-categories-design.md` §6.1, §6.5, §6.6, §10. No templates beyond what tests
need (none were needed).

## What shipped

- **`viewer/categories.py` (new, Flask-free).** Models `Artifact`, `ArtifactVersion`
  (`single_html` / `multi_file` / `none`), `ArtifactFile` (present / size match / SHA-256
  match), `CommentThread`, `ArtifactDataFile` / `ArtifactDataDocument`, `ScheduledTask`,
  `TaskRun`; loaders for the three categories; visible-text extraction (stdlib
  `HTMLParser`, `script`/`style`/`template`/`noscript` excluded); the script and
  external-resource probes §6.3 outcome 5 will use; `artifact_ids_in` (§6.5); and
  `read_member`, the one on-demand byte reader.
- **`Export`** gains `artifacts`, `artifact_data`, `scheduled_tasks`, `task_runs`, and
  `artifact_mentions`. `ToolResultBlock` now preserves `structured_content`.
- **Display order** is `created_at`, newest first; the active version is recorded, not
  assumed newest (`Artifact.active` falls back to the newest only when the active id is
  missing from the list).
- **Content decides.** Version layout comes from members (`<id>.html` vs `.files.json` +
  directory); a `page`'s content and comments are its root `.md` and `.json`, whatever
  they're named.
- **Preserve and flag**, each test-pinned: active version missing; version without files
  (not flagged for `page` versions, which carry none by design — V10); files present but
  unlisted (kept, never served); size / hash mismatch and listed-but-missing files;
  duplicate artifact id across parts (kept once, first wins, WARNING); unknown kind and
  visibility (raw); unreadable comments; an artifact directory without a descriptor
  (preserved with `no_descriptor`); version files no listed version claims; data for an
  absent artifact (orphans); runs for an absent task (orphans).
- **Owner-account check** mirrors the account-uuid check: a mismatch with `users.json` is
  logged, never fatal.
- **Cross-references (§6.5, provisional).** `artifact_mentions` maps each artifact to the
  conversations whose tool `input` or `structured_content` names it; prose is never used.
- **Search (§6.6).** Kinds `artifact` (title = active version's title; body = description
  + visible entry-page text, or the page Markdown, + multi-file Markdown) and
  `scheduled_task` (title = name, body = prompt), with a new `entity_id` column carrying the
  artifact or routine id for links. The row-count invariant moves in lockstep
  (`_expected_row_count` + artifacts + tasks; `test_index_export_populates_expected_row_count`
  updated in the same commit).
- **Byte access.** `artifact_part_opener()` (routes): inspect mode reads the inspected
  `frames` ZIPs from memory (`InspectState.part_blobs`); the primary export reads its
  stored files. Upload now points `source_paths` at the stored set after the swap (G4.3).
- **Parse cache key** covers `parser.py` and `categories.py` (G4.2).
- **Real-data invariants extended**: every `active_version` resolves, every multi-file
  version passes integrity (no unlisted files, every listed file present and matching),
  every run resolves or is preserved as an orphan.

## Disclosures (four-part)

**G4.1 — searchable text lives in the model.** *Observation*: the index is built from the
`Export` alone, so the text it indexes must be in the model or re-read at every index
build. *Letter*: "Bytes stay out of the parse cache … The pickle must not grow by artifact
payload size." *Intent*: the cache grows with prose, not payloads. *Decision*:
`Artifact.search_text` holds the visible text and Markdown only; scripts, styles, fonts,
bundles, and binary files never enter the model — pinned by the sentinel and size test.

**G4.2 — the parse-cache key.** *Observation*: the key hashed `parser.py` only; the new
models live in `categories.py`. *Intent*: a model change must invalidate the pickle.
*Decision*: the key hashes both modules (a one-time reparse for existing caches).

**G4.3 — upload source paths (phase 3's Q3).** *Observation*: an upload parsed the staged
set, so `source_paths` named the staging directory, which is renamed away — the footer
showed it, and artifact bytes would have been unreachable until restart. *Intent*: bytes
are read on demand from the stored set. *Decision*: after the swap, `source_paths` are
remapped to the stored files (the footer fix comes with it); the opener also falls back
to the stored set by filename. Pinned by a route-level test.

**G4.4 — where the models live.** *Letter*: "one internal model". *Decision*: the new
dataclasses live in `viewer/categories.py` and are fields of the one `Export`; the parser
still owns detection and assembly.

**G4.5 — what counts as integrity for the real-data invariant.** *Letter*: "every
multi-file version's integrity check passes". *Decision*: every listed file present with
matching size and SHA-256, and no unlisted files.
