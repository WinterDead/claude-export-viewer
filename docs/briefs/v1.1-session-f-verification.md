# v1.1 Session F — Verification

Two parts, per the brief's deliverables: the F2 sanitiser-boundary matrix (input HTML →
sanitised output, generated against the live pipeline) and the browser-pass results.

## Discovery notes (F1)

- `fenced_code` was already enabled (`viewer/render.py`, `_MARKDOWN_EXTENSIONS`); fenced blocks
  emit `<pre><code class="language-x">` with the standard `language-` prefix. No adaptation of
  the F2 pattern was needed.
- **Premise correction (flagged per the soft-gate rule):** the brief's F2 premise — "bleach
  currently strips `class` everywhere" — did not match the code. `_ALLOWED_ATTRS` already
  allowed `class` **unrestricted** on both `<code>` and `<pre>`. The F2 target state is defined
  exactly by the brief's test list, so implementing it *narrowed* the boundary (unrestricted on
  two tags → pattern-restricted on one). No widening of any kind occurred; the overriding hard
  stop was not triggered.

## Soft-gate resolution: the `powershell` language module

The first browser pass found 50 of 70 hinted blocks on the most code-dense page falling back to
plain text: their hint is `powershell`, which is **not** in highlight.js's common-languages
build. A census across the whole reference export: of ~189 hinted fences, **170 hint
`powershell`** (~90%); the remainder are toml (9, also absent from the common build), bash (5),
css (3), yaml (1), batch (1). Shipping the common build alone would have made highlighting a
near-no-op for this archive.

Resolution (flagged per the soft-gate rule — the brief specified "one minified JS file"): the
common build is vendored exactly as specified, **plus** the single upstream `powershell`
language module from the same `cdn-release` 11.11.1 tag, same BSD-3-Clause licence, loaded
after the core bundle. The long tail (toml, batch) stays on the graceful plain-text fallback.
