# v1.2 — Session K Brief: simple inspector (read-only inspect mode)

Read CLAUDE.md and `docs/plan.md` before anything else. This is the first v1.2 session: a
read-only inspect mode for viewing an export that isn't the stored one. Design decisions
below are operator-ratified, 2026-07.

## Scope

One feature, complete with its help copy and tests. No export-to-file work (Sessions M/N),
no README changes (close-out session), no changes to upload, tagging, or parsing semantics
for the primary export. There are no open design decisions in this brief.

**Hard stops for this session, overriding everything below**: any write to disk originating

## Design (locked)

- **Inspect mode is read-only, one-off, and ephemeral.** It exists to look at a non-primary
  export temporarily — a test corpus, a second account's archive — and is independent of
  any future profile/tag-state feature. It is a view mode, nothing more.
- **Entry**: a new **Inspect** item in the nav, its own page with a file picker. Deliberately
  distinct from Upload (which replaces stored data); the two verbs must never blur.
- **The no-trace rule**: an inspected export is parsed **in memory** and leaves **no disk
  artifacts whatsoever** — the uploaded bytes are not saved under `cache/`, no parse pickle
  is written, no `upload_history` row is recorded, and its search index is an **in-memory
  SQLite database** discarded on exit. Re-inspecting the same file re-parses; that cost is
  accepted for a one-off mode. (This also gives the v1.2.5 audit a one-line story:
  inspection cannot leak because inspection never writes.)
- **Isolation is structural**: while inspecting, all mutating routes refuse — tagging
  (single and bulk), purge, and upload. Tag dropdowns, the tag filter, and the bulk action
  bar's mutating actions are absent from inspect-mode pages. (Forward note: when export
  actions land in Sessions M/N, they are non-mutating and *will* be available in inspect
  mode — that's a primary use case.) The Upload page, while inspecting, shows a notice and a
  disabled form rather than vanishing from the nav.
- **Mode signal**: a persistent full-width banner on every page while inspecting, in a third
  colour distinct from the amber orphan banner and the red load-error banner, containing the
  exit control.
- **Ephemeral**: inspect state is in-process memory only. "Return to my export" restores the
  primary source through the normal load path (the primary's pickle cache makes this fast;
  whether the primary stays resident during inspection is Code's choice). An app restart
  always comes back on the primary export.
- Inspected files run the same parse-validate pipeline with the same 200 MB cap; a corrupt
  file errors on the Inspect page (message adapted from the existing upload parse-error
  style — mechanical soft gate) and the currently viewed export is untouched.
- Single-process dev server: inspect state is app-global, so concurrent browser tabs share
  it. Accepted for a single-user localhost tool; note it in the report, don't engineer
  around it.

<!-- VERBATIM -->
## Inspecting another export

Sometimes you want to look inside an export without making it yours — a second account's
archive, a colleague's export, or a test file. The Inspect page opens an export temporarily
and read-only: no tagging, nothing saved to disk, nothing recorded in upload history, and
your own export and tags stay exactly as they were. A banner reminds you which file you're
inspecting; the **Return to my export** button in the banner (or simply restarting the app)
puts everything back. To replace your stored export instead, use Upload.
<!-- END VERBATIM -->

## Tests (this list defines the target state)

1. Inspecting a valid fixture zip swaps the view, shows the banner with the filename, and
   renders conversations/projects/memory from the inspected export.
2. All mutating routes refuse during inspection (tag, bulk tag, purge, upload POST), and
   `cache/viewer.sqlite` is byte-identical before and after an inspect session that browses
   and searches.
3. No-trace: a directory snapshot of `cache/` before inspection equals the snapshot after
   (no new files, no modified files).
4. No `upload_history` row is created by inspection.
5. Search works against the inspected export and the primary FTS index is unchanged by it.
6. "Return to my export" restores the primary view; the banner is gone; tagging works again.
7. A corrupt zip errors on the Inspect page; the previously viewed export remains loaded.
8. Tag dropdowns, tag filter, and mutating bulk actions are absent in inspect mode; the
   Upload page in inspect mode shows the disabled state.
9. Banner text matches the authored copy; banner present on at least home, conversations,
   and help while inspecting.
10. Help section claims verified (existing help verify-negative tests still pass).
