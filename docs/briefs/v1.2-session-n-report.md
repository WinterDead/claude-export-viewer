## The WYSIWYG note the brief requires (B4)

Links inside collapsed sections appear in the appendix **only if the section is open** —
consistent with the print pass's WYSIWYG rule. Mechanically: the appendix is built on page
load and *rebuilt on `beforeprint`*, so the open/closed state that matters is the one at
print time (a thinking block opened after page load contributes its links; one closed
again drops them, and numbering stays consistent between markers and appendix). Verified
live in the embedded Chromium (see the in-session browser pass below).

## Soft gates and judgment calls (flagged prominently)

1. **README bullet formatting (the brief's named mechanical soft gate):** lead terms
   bolded (`**Inspect mode** — …`) to match the Features list's convention; wording
   untouched.
2. **Row-checkbox aria-label** changed from "Select for bulk tagging" to the neutral
   "Select conversation" — the checkbox now drives export selection in both modes, and in
   inspect mode tagging doesn't exist. Structural consequence of A2.
3. **Session K test contract updated:** `tests/test_inspect.py` pinned "no bulk bar, no
   checkboxes, no controller in inspect mode"; A2 mandates exactly that bar. The test now
   pins the new contract (bar present, export-only, every tagging control absent).
4. **Appendix rebuild on `beforeprint`** in addition to "built on page load": load-time
   state alone would freeze the appendix at "all thinking collapsed", contradicting the
   brief's only-if-open sentence. The rebuild keeps marker/appendix numbering consistent
   with the state actually being printed.
5. **Appendix dedup unit test:** the shared-number logic was *not* extracted into a
   separately unit-tested function — the repo has no JS test infrastructure, and the brief
   conditions the unit test on extraction. Pinned instead by content guards
   (`numberByUrl`, print-only classes, `beforeprint`) and exercised live in the browser
   pass (repeated URL → one number; closed-section exclusion; renumbering).
6. **Copy failure surfacing:** on a fetch/clipboard failure the button logs to the console
   and raises a plain `alert` — without it a failed copy would be indistinguishable from a
   successful one. (Observed in the driven-browser pass: the Clipboard API refuses writes
   when the document isn't focused — an automation artifact; a real click has focus.)
7. **`style.css` header comment** updated — it described the print block as "the
   print-friendly skeleton", which B1–B6 made false. Comment-only.
8. **Print branch label case:** the screen label is uppercased by `text-transform`; print
   resets it so the printed line reads as the authored copy. The DOM text was always the
   authored bytes; this is presentation only.
9. **`_parse_content_block` signature** tightened from `ContentBlock | None` to
   `ContentBlock` (it can no longer return `None`), and the caller's drop-guard removed.
