# Claude Export Viewer — v1.1 Session F Brief

Read CLAUDE.md and docs/plan.md before doing anything else.

This session adds syntax highlighting to rendered code blocks via a **vendored** copy of highlight.js running client-side. It deliberately touches the bleach allowlist — the app's sanitisation security boundary — in exactly one narrowly-scoped way, specified below. Gate language: **soft gate** = resolve if obvious and within intent, flag prominently; **hard stop** = end the session and report without implementing.

**The overriding hard stop for this session: any change to the bleach allowlist beyond the single rule in F2 — any additional tag, any additional attribute, any widening of the class-value pattern, any `style` attribute under any circumstances — ends the session for a chat decision. No exceptions, regardless of how reasonable the widening looks.**

## Why client-side rather than Pygments

Server-side Pygments would require letting its `<span class="…">` token markup survive bleach, loosening the allowlist for *all* rendered content. Client-side highlighting works on the already-sanitised DOM, so the boundary stays effectively closed. This was decided in chat; don't relitigate.

## F1. Discovery first (small, in-session)

Verify what the markdown pipeline actually emits for fenced code blocks:

- Confirm which python-markdown extensions are enabled and whether fenced blocks produce `<pre><code class="language-x">` (the `fenced_code` extension's default `language-` prefix).
- Soft gate: if `fenced_code` isn't enabled, enabling it is in scope (fenced blocks in real conversation content should render as code blocks regardless of highlighting).
- Soft gate: if the emitted prefix differs from `language-`, adapt the F2 pattern to the actual prefix and flag it.

## F2. The one allowlist change

Bleach currently strips `class` everywhere, which also strips the language hint off `<code>`. Add exactly one rule, via an attribute callable:

- `class` is allowed **only on `<code>`**, and **only when the entire value matches** `^language-[A-Za-z0-9_+#.-]+$`.
- Everything else about the allowlist is unchanged.

Tests for the boundary (verify-negatives, exhaustive):

- `<code class="language-python">` → class survives.
- `<code class="language-c++">`, `language-c#`, `language-objective-c` → survive (the pattern's `+#.-` exists for these).
- `<code class="evil language-python">` (multi-class) → stripped (the *entire* value must match).
- `class` on `<pre>`, `<span>`, `<div>`, `<a>` → stripped.
- `<code class="anything-else">` → stripped.
- Regression: event-handler attributes, `style`, and script tags still stripped everywhere; the existing `<mark>` allowance still works.

## F3. Vendoring

- highlight.js, **common-languages build**, vendored under `static/vendor/highlightjs/`: one minified JS file, one CSS theme, and the upstream LICENSE file alongside them (BSD-3-Clause — required for the public repo). Record the exact version in a one-line README in that directory.
- **No CDN, ever.** CLAUDE.md's no-external-network-calls constraint and the help page's "nothing leaves your computer" claim are load-bearing (the Session C matrix verified them). A CDN `<script>` tag would falsify both. Hard stop if vendoring proves impossible for some reason.
- Theme choice: a light theme consistent with the app's existing palette, with reasonable contrast. Your pick; name it in the report.

## F4. Initialisation and scoping

A small init in the existing JS layer, on DOMContentLoaded:

- Highlight `<pre><code>` blocks in rendered-content containers: conversation messages, knowledge documents, memory blocks, and the help page.
- **Skip any code element containing a `<mark>` descendant.** highlight.js rebuilds the element from its text content, which would destroy search-hit highlighting. In practice this means search-result snippets are never highlighted — that's intended, not a bug.
- When a `language-x` hint is present, use it; otherwise let highlight.js auto-detect.
- Pages re-render server-side on navigation, so one-shot init is sufficient; no mutation observers.

Soft gate: if the browser pass shows visible jank on the largest real conversation, defer highlighting via `requestIdleCallback` (or equivalent) and flag it. Don't add laziness preemptively.
