`app.config["SECRET_KEY"] = secrets.token_hex(32)` inside `create_app`, with an existing

two `create_app` calls yield different keys (fresh per start, which a literal or env
fallback would fail), and the key is a 64-character pure-hex string.

## Operator note — Windows launcher test procedure

Behaviours worth human verification on a real Windows machine (double-click `run.bat`
throughout — the PowerShell 5.1 path is the one users get):

1. **Healthy-path regression** — with a complete `.venv`: no rebuild notice, no reinstall,
   app starts, browser opens on `http://127.0.0.1:5000/`.
2. **Pip-less venv rebuild** (the new behaviour) — delete `.venv`, recreate it with
   `py -3 -m venv --without-pip .venv`, then run: expect the rebuild notice, a fresh venv,
   a full dependency install, and a normal start.
3. **Em-dash rendering under PowerShell 5.1** — in step 2's console output, the notice must
   read "incomplete — rebuilding", not mojibake (this validates the new UTF-8 BOM; a pwsh 7
   run would pass even without the BOM, so the `run.bat` path is the one that matters).
4. **Creation-failure branch (unchanged)** — optional: make `.venv` creation fail (e.g. a
   read-only leftover `.venv` directory after deleting `python.exe` from it is awkward to
   stage; simplest is a file named `.venv` blocking the mkdir). Expect the existing
   "Creating .venv did not work." message and the window staying open via `|| pause`.
5. **Loopback binding** — with the app running, `netstat -ano | findstr :5000` shows
   `127.0.0.1:5000` (not `0.0.0.0`); from another LAN device the port is unreachable.
6. **Port fallback with the new flag** — occupy 5000, run: app lands on 5050 and the
   "Using port 5050" line prints.
7. **All-busy manual line** — occupy all four ports (5000/5050/5051/5052), run: the printed
   manual command includes `--host 127.0.0.1 --port 8080`.
