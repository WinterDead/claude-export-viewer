## Code review: claude-export-viewer (branch `session-u`, after commit 4fa828f)

Scope: a read-only review of `viewer/`, `app.py`, `templates/`, `static/`, `tests/`,
`tools/` and the launchers, checked against CLAUDE.md and the two design records. The
reviewer ran the test suite once: **826 passed, 4 skipped** (the opt-in real-data tests).
It did not run the app, so findings marked *(uncertain)* are worth a quick check.

### 1. Technical debt

- **Medium — `viewer/routes.py:1079-1242` vs `1317-1429`: Upload and Inspect duplicate
  the whole submission pipeline.**
  - Both routes repeat the extension check, sniffing, A6/D2 skipping, the manifest part
    map, `_part_order`, last-wins de-duplication, and the "manifest alone" errors.
  - The copies have already drifted. When a category is supplied twice, Upload deletes
    the earlier file from staging and Inspect just drops it from the list.
  - *Rec:* one "classify and slot a submission" function behind an opener abstraction.
    Each route then does only its own storage step.
- **Medium — `viewer/artifact_views.py:48`, `app.py:40-42`: artifact views are coupled
  to `routes.py` internals.**
  - `artifact_views.py` imports the private `_current_export` and `bp` from `routes.py`.
  - Its routes register only as a side effect of `app.py` importing the module.
  - `routes.py` is already about 1,700 lines.
  - *Rec:* move the shared request helpers into a small module and register the artifact
    routes explicitly.
- **Medium — `pyproject.toml:15`, `viewer/render.py:130`: the sanitiser rests on
  `bleach`, which upstream deprecated in 2023.**
  - *Rec:* record the dependency risk in the plan.
  - Schedule a move to a maintained sanitiser, for example `nh3`, kept behind the same
    allowlist tests.
- **Low — two timestamp parsers disagree.**
  - `parser._parse_dt` (`parser.py:1645`) turns a missing or bad value into the 1970
    epoch.
  - `categories._ts` (`categories.py:52`) turns it into `None`.
  - *Rec:* converge on `None` plus a display fallback.
- **Low — comment and docstring drift.**
  - `routes.py:3-5`: the module docstring still says the memory view is the current step.
  - `routes.py:979-983`: a comment still says "four category zips plus the manifest".
  - `cache.py:5-12`: the docstring says the cache key covers `parser.py` only.
  - `search.py:122-123`: says the rebuild is "transactional". In fact `executescript`
    commits the DROP/CREATE outside the population transaction.
- **Low — `run.sh:100`, `run.ps1:145`: the launchers reinstall only when one of four
  hard-coded imports fails.**
  - A dependency added later won't be installed for existing users.
  - *Rec:* compare an installed-requirements stamp with `pyproject.toml`.

### 2. Risk: correctness and security

- **High — `templates/_message.html:50` and `:104`: links from the export go into
  `href` with no scheme check.**
  - Both `rich_link` `link.url` and citation `details.url` are rendered this way.
  - Jinja escaping does not neutralise `javascript:`, and the app's own pages send no
    Content-Security-Policy.
  - A crafted archive opened in Inspect therefore runs script in the viewer's origin when
    the link is clicked. That script can read the CSRF token and post to the app's routes.
  - Markdown links and the manifest page are guarded; these two paths are not.
  - *Rec:* one http(s)-only filter for every URL that comes from an export, plus a
    restrictive CSP on the app's pages.
- **High — a set without conversations or projects makes every tag an orphan, and the UI
  then offers to purge them all.**
  - Evidence: `viewer/state.py:77-83`, `templates/orphans.html:103-119`,
    `routes.py:1589-1601`.
  - Example: upload a set containing only `frames`. Every tag row lands in the
    orphan-conversation bucket, and the banner invites a purge.
  - *Rec:* when the primary set lacks the conversations or projects category, suppress
    orphan classification and the purge for that dimension.
- **Medium — `viewer/render.py:97-99` plus bleach's default protocols: remote images in
  Markdown survive sanitising and load.**
  - This covers messages, memory, project documents, page artifacts, and content files.
  - It contradicts the principle "no network reachable from anything the viewer renders"
    (`docs/export-categories-design.md:37-38`).
  - *Rec:* drop or neutralise non-relative image sources, or send `img-src 'self' data:`
    on the app's pages.
- **Medium — `routes.py:1196-1220`: the upload swap can fail halfway with no rollback.**
  - A failed rename can leave the previous set stranded in `active_export.old`.
  - If `index_export` raises after the disk swap, the new set is on disk while memory
    still holds the old one.
  - The stage directory has a fixed name.
  - *Rec:* restore `old` when the rename fails, and index before swapping (or roll back).
- **Medium — `app.py:128` and `:141`: startup falls through only on
  `ExportFormatError`.**
  - Other parser exceptions, or a failed `write_cache` (for example a full disk), stop
    the app from starting.
  - The same exceptions surface as raw 500 errors on Upload and Inspect.
  - *Rec:* treat a cache-write failure as a warning, and convert parser exceptions to
    `ExportFormatError` at the loader boundary.
- **Low (uncertain) — `routes.py:1340`: Werkzeug spools multipart bodies over 500 KB to a
  temporary file, so Inspect's "no-trace" claim is not literally true.**
  - Recorded in Session K as accepted. *Rec:* disclose it in Help, or use a custom
    `stream_factory` for `/inspect`.
- **Low — `routes.py:183`: `_safe_redirect` accepts `/\host`.**
  - *Rec:* reject a backslash in the second position.
- **Low — `cache.py:109-116`: the pickle is unpickled before its key is compared, and the
  load catches only four exception types.**
  - *Rec:* keep the key in a separate header, and catch `Exception` around the load.
- **Artifact sandbox (`viewer/artifact_views.py`): no material findings.**
  - One note: `'self'` in `img-src` and `style-src` lets an artifact send GET requests to
    viewer routes. That is harmless while every mutating route is POST with CSRF; keep it
    that way.

### 3. Test gaps

- **High:** no test that a `javascript:` URL in a `rich_link` or a citation is
  neutralised.
- **Medium:** no parser tests for wrong-typed fields. Examples: an integer timestamp, a
  block that isn't a dict, an `account` that is a string, a message without a uuid,
  invalid UTF-8.
- **Medium:** no test of a category subset's effect on tags, the orphan banner, or purge.
- **Medium:** the upload swap's failure paths are untested.
- **Low — `tests/real_exports.py:133-139`: the "runs neither resolved nor preserved"
  invariant is a tautology.**
  - It is computed as runs minus resolved minus orphans, so it is always 0.
  - `:162-163` also re-asserts a row count that `index_export` already enforces.
- **Low:** no friendly 413 handler and no test for `MAX_REQUEST_BYTES`.

### 4. Dead code

- **Low:** `parser.load_export_from_bytes` has no production caller, and the
  `inspect.py:6` docstring still names it.
- **Low:** `state.orphan_conv_uuids` and `state.orphan_project_uuids` are unused.
- **Low:** `routes._PART_SUFFIX_RE` duplicates `parser.PART_FILENAME_RE`.
- **Low:** `cache.py:55-56` has an unreachable defensive branch.
- **Low:** artifact `flags` and `unlisted_files` are computed but no template renders
  them. The `categories.py` docstring says they exist "so the pages can surface it".
- **Low:** `ALL_CATEGORIES` holds only the core four, which the name doesn't say, and
  `CORE_CATEGORIES` is an alias for it.

### 5. Where the next export-format change will hurt

- **F1, High — the core parser assumes types, while `categories.py` is defensive.**
  - Examples: `(rec.get("account") or {}).get`, `raw["uuid"]`, `raw.get` on a
    possibly-non-dict block, `creator.get`, `.items()`, `int(file_size)`,
    `fromisoformat` on a non-string.
  - `_read_json` catches only `JSONDecodeError`.
  - One changed field type escapes as an exception that isn't `ExportFormatError`.
  - *Rec:* bring the core loaders up to `categories.py`'s style.
- **F2, High — `parser.py:567-592`: category recognition is all-or-nothing.**
  - One new member type in a zip makes the whole category "unrecognised".
  - *Rec:* recognise a category by its defining members, keep any extras, and log a
    WARNING.
- **F3, Medium:** a memories zip with more than one file, or with parts that disagree,
  fails the whole set.
- **F4, Medium:** adding a category touches many places — the constants, sniffing,
  validation, loading, the `Export` fields, the three-way search lockstep, the nav flags,
  and `MAX_REQUEST_BYTES`.
  - `MAX_REQUEST_BYTES` is still sized for five files, while a current set now has eight
    or more.
  - *Rec:* a per-category registry, and a request cap derived from `KNOWN_CATEGORIES`.
- **F5, Low — `parser.py:1580-1629`:** the legacy multi-batch merge drops
  `memory_files` and `login_events`, and logs duplicates at DEBUG rather than WARNING.

### What's in good shape

The artifact preview is the security boundary that matters most, and it is well
designed and well tested:
- It layers the sandbox attribute, a per-response sandboxing CSP, and lookup-only file
  serving.
- There are traversal and encoding tests.
- Downloads are built in memory, with sanitised member names.

`categories.py` follows the preserve-and-flag rule throughout.

The upload path is careful: parse-before-replace staging, and per-file skipping of
unrecognised (A6) and unreadable (D2) files.

Protections elsewhere hold:
- CSRF covers every POST.
- Inspect mode refuses every mutation structurally.
- The search index guards itself with a row-count check.
- The parse cache is written atomically.

The tests are broad, fast, and synthetic only.

The work ahead is mostly bringing the older core parser and the template URL sinks up to
the standard the v1.4.0 code already meets.
