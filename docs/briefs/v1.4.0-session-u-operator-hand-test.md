# v1.4.0 operator hand-test brief — export categories, Artifacts, Scheduled tasks

Committed deliverable of Session U phase 7. It exercises v1.3.1 and v1.4.0 against your own
exports in the browser you normally use — the things the suite and the session's browser
passes could not observe (see the phase 5 report's layer table). Every **Expect** line is
derived from the code or a test, cited in brackets. Report in the format at the end.

**Never paste real content into the report** — no titles, names, prompts, file names, or
text from your exports. Report what each element is *labelled* on screen and whether it
behaved as expected; counts are fine.

Throughout, "your exports" means the ones you keep outside the project folder: a current
set with all seven category ZIPs plus its manifest (**the full set**), a current set with
five ZIPs including `frames` (**the earlier set**), and **your older single ZIP**.

## 0. Freshness gate

1. From the project root:

   ```
   git fetch
   git log --oneline -3 origin/session-u
   ```

   **Expect**: the top commit begins `v1.4.0:` (or a later review commit). If not, stop.
2. `git switch session-u` and `git pull`, then run the suite:

   ```
   .venv\Scripts\python.exe -m pytest -q
   ```

   **Expect**: all pass, zero failures; two real-data tests skip with "VIEWER_REAL_EXPORT_DIR
   is unset" [`tests/real_exports.py`]. A red suite is a hard stop.

## 1. Backup and reset

The startup load order is **(1)** `cache\active_export\` → **(2)** `cache\active_export.zip`
→ **(3)** the built-in sample [`app.py`, `_load_default_source`]. The `data\` step is gone
since v1.3.1. Fresh state defeats steps 1 and 2 and drops the parse cache:

1. Stop the app.
2. Back up `cache\viewer.sqlite` (your tags) somewhere outside the project.
3. Move `cache\active_export\` and `cache\active_export.zip` (whichever exist) outside the
   project — this defeats load-order steps 1 and 2 — and delete
   `cache\parsed_export.pkl`.
4. **To restore afterwards**: stop the app, move the folder or ZIP back into `cache\` (or
   re-upload), and restore `viewer.sqlite` if anything happened to it.

Start the app with `run.ps1` for each scenario; clear the browser's cookies for the app's
address before scenario 5 so the hide setting starts off.

## 2. The full eight-file upload (the v1.3.1 regression)

1. Start the app. **Expect**: the sample loads (footer names the sample file), no banners
   [`test_fixture_loads_when_no_set_is_stored`].
2. Upload all eight files of the full set in one pick.
   **Expect**: redirect to Home; no banner of any kind
   [`test_full_eight_file_set_through_the_real_upload_form`]; nav shows `Artifacts`
   right after `Memory`, then `Scheduled tasks` [`test_nav_entries_show_only_with_their_categories`].
3. Check `cache\active_export\`. **Expect**: exactly the eight files, original names.
4. Check the footer. **Expect**: paths under `cache\active_export\`, not a `.stage` folder
   [`test_upload_points_sources_at_the_stored_set`].

## 3. An unknown extra file

1. Make a ZIP containing any single small file (not an export), name it
   `future_category-000.zip`, and upload it together with the full set.
   **Expect**: the upload loads; a notice under the nav reads "future_category-000.zip
   isn't a file this version of the viewer recognises, so it was skipped. The rest of your
   export loaded."; reloading the page removes the notice
   [`test_unknown_ninth_zip_upload_loads_with_d1`].
2. Upload only that ZIP. **Expect**: an error, "future_category-000.zip isn't a recognised
   export file.", and your export unchanged [`test_all_unrecognised_submission_still_errors`].

## 4. The Download links page with a real (expired) manifest

1. Upload page → "Only have the manifest file? Get your download links."
   **Expect**: a page titled `Download links` with a `Manifest file` picker and a
   `Show download links` button [`test_manifest_page_copy`].
2. Choose the full set's manifest and submit.
   **Expect**: `Export created …`, the warning beginning "These links are personal and
   expire about 24 hours…", and a `File` / `Category` / `Download` table with one
   `Download` link per file [`test_manifest_page_lists_links_and_writes_nothing`].
3. Hover one `Download` link (don't click — the link is expired and personal).
   **Expect**: an `https` address. In DevTools → Network, **expect** no request to any
   host other than the app (the viewer never fetches the links).
4. Check `cache\` modification times. **Expect**: unchanged by this page.

## 5. Legacy memory, setting off and on

1. Memory page (full set loaded). **Expect**: a `Hide legacy memory` checkbox, unticked;
   group order `Memory files`, `Project memories`, then `Legacy memory (no longer
   updated)` collapsed; opening it shows the note "This is the summary from Claude's
   previous memory system…" [`test_legacy_memory_orders_groups_and_collapses`].
2. Search for a word you know is in your older memory summary. **Expect**: the memory hit is
   labelled `Legacy memory` [`test_search_hit_carries_the_legacy_label`].
3. Tick `Hide legacy memory`. **Expect**: the page reloads with the box ticked and the legacy
   group gone; the same search no longer shows the memory hit
   [`test_hide_setting_through_the_rendered_control`].
4. Restart the app. **Expect**: still hidden (the cookie persists).
5. Untick it. **Expect**: the legacy group returns.
6. Home page: note what the memory block is labelled. (Record question Q2: Home is outside
   record §7; just report what you see.)

## 6. Your older single ZIP

1. Leave `Hide legacy memory` **ticked** and upload your older single ZIP.
   **Expect**: no banner; no `Artifacts` or `Scheduled tasks` in the nav; the Memory page
   shows `Conversation memory` as the first group and **no** checkbox
   [`test_hide_setting_never_hides_a_summary_without_memory_files`].
2. Account page. **Expect**: a login-history table if this archive carries one; otherwise
   "This export doesn't include login history." [`test_account_page_shows_legacy_login_history`].
3. Re-upload the full set before continuing.

## 7. Inspect with each export

With the full set as your stored export and `Hide legacy memory` ticked:

1. Inspect the earlier set (all its files, manifest included). **Expect**: the blue inspect
   banner; **no** degraded banner, because every category its manifest lists is supplied
   [`test_manifest_banner_names_missing_later_categories` shows the opposite case]; nav
   shows `Artifacts` and **not** `Scheduled tasks`; the Memory page shows the legacy group
   (never hidden while inspecting) and **no** checkbox
   [`test_inspect_obeys_section_7_regardless_of_the_cookie`].
2. Inspect the older single ZIP. **Expect**: `Conversation memory` first, no checkbox.
3. Inspect the full set. **Expect**: Artifacts pages work while inspecting (open one
   artifact and its preview) [`test_inspect_serves_from_memory_and_leaves_cache_identical`].
4. `Return to my export`. Check `cache\` modification times: **expect** unchanged by the
   inspections.

## 8. Artifacts pages and the preview's network behaviour

Open DevTools (Network and Console tabs) before each step.

1. `Artifacts`. **Expect**: heading `Published artifacts`; columns `Title`, `Type`,
   `Versions`, `Updated`; sort links `Recently updated`, `Recently created`, `Title (A–Z)`;
   types read `Artifact` or `Document` [`test_artifact_list_copy_and_sorts`].
2. Open a web-page artifact with several versions. **Expect**, top to bottom: title; type ·
   visibility; description; `Version` list with `Active version` beside one; `Preview`;
   `Download`; `View source`; `Files` (`Path`, `Type`, `Size`, `Check`, every row `OK`);
   `Content files`; `Saved data` if it saved any; `Mentioned in conversations`
   [`test_detail_sections_in_record_order`]. If its page uses scripts, the notice "This page
   uses scripts, which the viewer doesn't run…" appears above the preview.
3. **The preview's network behaviour.** In Network, filter to the preview's requests.
   **Expect**: requests only to the app's own address (`…/artifacts/…/f/…`); **zero**
   requests to any other host [record §6.3 outcome 4]. In Console, **expect** "Blocked
   script execution … sandboxed and the 'allow-scripts' permission is not set" for a
   script-using page — the inline script did not run [record §6.3, phase 5 assignment].
4. If the artifact ships a font file (`font/woff2` in its Files table), **expect** the
   preview's text in that font and no CORS error for it in Console [phase 5 G5.3].
5. Copy the preview's address (right-click the frame → open frame in new tab, or take a
   `…/f/index.html` URL from Network) and open it directly in a tab. **Expect**: it renders;
   Console shows the same blocked-script message (sandboxed even outside the frame).
6. Pick an older version from the list. **Expect**: only that version's preview loads.
7. Open a `Document` artifact. **Expect**: its text rendered as formatted Markdown, no
   frame, a `Download` button; `Comments` with `On “…”` lines (and `Resolved` badges where
   resolved) if it has comments [`test_page_kind_renders_markdown_and_comments`].
8. In a conversation that published an artifact, **expect** an `Open in Artifacts` link on
   the tool card that leads to it [`test_tool_card_links_to_artifacts`]. (Phase 1 finding
   F2: expect this on few artifacts — most of yours are named only in prose.)
9. Download each kind once (web page `.html`, multi-file `.zip`, document `.md`).
   **Expect**: files open; `cache\` unchanged [`test_downloads_write_nothing_under_cache`].

## 9. Scheduled tasks

1. `Scheduled tasks`. **Expect**: columns `Name`, `Schedule`, `Enabled`, `Created`,
   `Last run`; schedules read `Repeats: …` or `Once: …`; `Yes`/`No`; `Never` for tasks
   without runs; each task has a collapsed `Prompt`; `Run history` lists runs per task
   with `Scheduled for`, `Started`, `Finished`, `Status`, `Session`
   [`test_scheduled_tasks_page_copy`].
2. Search for a word from one task's prompt. **Expect**: a `Scheduled tasks` result linking
   to that task's row [`test_search_hits_link_to_artifacts_and_tasks`].

## 10. Dark mode on every new page

Set Theme to Dark. Visit `Download links`, Memory (legacy group open), `Artifacts`, an
artifact detail, a `Document` artifact, `Scheduled tasks`, and a conversation with a
collapsed long tool result. **Expect**: no light patches, unreadable text, or white
tables around the app's own content [`test_new_surfaces_use_palette_tokens_only`]. (The
preview frame shows the artifact's own colours — that's the artifact, not the theme.)

## 11. Printing an artifact page

Print (or Save as PDF) an artifact detail page with a preview. **Expect**: the `Preview`
heading followed by the line "Preview not printed."; no frame, no buttons; nav and footer
absent [`test_preview_print_placeholder`].

## Report format

For each scenario and step: **PASS** or **FAIL**, then the elements you saw *as labelled
on screen* (button text, headings, column names, notices) and any deviation from the
**Expect** line. Counts are fine; real titles, names, prompts, or text are not. File the
report as `docs/briefs/v1.4.0-session-u-operator-hand-test-report.md`.
