## Print-assessment highlights

- **The skeleton's force-open `<details>` hack no longer works in modern engines.** Chromium
  now renders closed `<details>` content behind a `::details-content` pseudo-element with
  `content-visibility: hidden`, which the skeleton's `display: block !important` override
  cannot defeat; Firefox shipped the same model in 2025. Verified empirically in the app's
  embedded Chromium (probe details in the assessment).
- Consequently a printed conversation today shows closed thinking and attachment blocks as
  **unlabelled empty husks** (the companion rule hides their summaries, so not even a
  "[Thinking]" line survives), and opened ones as unlabelled full text. The summary-hiding
  rule is itself cascade-inconsistent: memory/help/project-doc summaries declare
  `display: flex` at class specificity and still print.
- The design record's alignment requirement is carried as the core recommendation: deliberate
  WYSIWYG printing (drop both `<details>` print rules; closed blocks print as their honest
  summary line, the screen state becomes the print-time toggle), with an explicit
  do-not-resurrect note for blanket force-open via the modern pseudo-element.
- Secondary recommendations: wrap code in print (long lines currently clip), hide
  `.memory-block-controls`, prune the unsatisfiable `section` break rule, plus three
  operator-call candidates (branch-point label line, absolute timestamps, content-link URLs).
