## What shipped

- **Detection (§3).** `frames`, `artifact_data`, and `claude_code_cloud` signatures in
  `sniff_container`; `CORE_CATEGORIES` (the original four), `LATER_CATEGORIES`, and
  `KNOWN_CATEGORIES` in the parser.
- **A6 (D1) and structural validation (D2).** Upload and Inspect skip an unrecognised file
  with D1 and never store it; a later-category file that fails `validate_category_zip` is
  skipped with D2; the rest loads. A submission with no recognised file keeps the existing
  error. Mixed legacy + current is still refused. The path loader (stored sets, real-data
  tests) skips an unrecognised ZIP beside category ZIPs with a WARNING, and re-validates
  later categories, skipping a failing part with a WARNING.
- **A7 banner (D3).** With a manifest, the expected categories are its distinct categories:
  the lead counts against that number and every missing one gets its line, unknown names by
  raw name. Without one, only the four core categories count. The expected-vs-supplied
  line is unchanged.
- **Kept, not displayed (§5.1, D4).** Later categories are stored in the set, counted in the
  summary and fingerprint, validated, and listed in `Export.categories`. D4 shows on Home
  when the loaded set carries any of them, and in Help.
- **`document` block (§5.3, D6).** `DocumentBlock` replaces the `UnknownBlock` fallback:
  reading-view card `Document` / title or `Untitled document` / the note; export line
  `> **[Document: {title}]**`. `KNOWN_BLOCK_TYPES` gains `document`.
- **Legacy login history (§5.4).** A legacy archive with a root `login_history.json` fills
  the same `login_events` slot; the Account page shows it.
- **Legacy memory (§7, D5).** Legacy whenever the set has memory files. Memory page order
  Memory files → Project memories → Legacy memory (a collapsed `<details>` headed and
  annotated per D5); search hit label `Legacy memory`; the `Hide legacy memory` control
  (off by default) persists `viewer_legacy_memory` (HttpOnly, one year) and hides the
  group and the search hit only in the legacy state. Inspect ignores the cookie and renders
  no control.
- **Manifest links page (§8, D7).** `/manifest`: one picker, parsed in memory, nothing
  stored; created line, warning, `File`/`Category`/`Download` table; anchors only for
  `https` URLs with a host, `rel="noopener noreferrer"`; `(link not shown)` otherwise; the
  error copy; linked from Upload (D7 pointer) and Help.
- **Launchers (§5.7, D13).** `run.sh` suppresses Python's own venv output and ends the
  friendly message with the D13 sentence. `run.ps1` probes `py -0p` and tries each listed
  version that meets the minimum by its qualifier before declaring "too old"; the
  too-old message gains the D13 sentence. BOM preserved; both scripts parse.
- **Amendments** A6, A7, A8 applied verbatim to `docs/format-support-design.md` (A5 in
  phase 2).
- **Fixtures.** `current/` now carries the full eight-file delivery (manifest listing seven
  categories plus seven ZIPs) — the G1.5 deferral closed in the same commit as A6.
- **1.3.1 close.** README "Getting your export" replaced with D7's paragraph; Help updated
  (D4, D5 Memory and Appearance copy verbatim, Download links pointer, plus drafted
  passages below); `docs/briefs/v1.3.1-release-notes.md` verbatim from D10; the plan
  records v1.3.1's shipped items as locked decisions and drops the two launcher items from
  the "Later" list; `pyproject.toml` bumped to `1.3.1` in the commit beginning `v1.3.1:`.
  No tag.

## Disclosures (four-part)

**G3.1 — category constant names.** *Observation*: `ALL_CATEGORIES` means "the four" across
the code and tests. *Letter*: record §4 names the four the "core" set. *Intent*: no silent
change of meaning. *Decision*: `ALL_CATEGORIES` keeps its meaning (aliased
`CORE_CATEGORIES`); `KNOWN_CATEGORIES` is the seven.

**G3.2 — how D1/D2 reach the page.** *Observation*: Upload and Inspect redirect on success.
*Letter*: D1/D2 are notices. *Intent*: the user sees what was skipped. *Decision*: a
one-shot flashed notice (Flask's signed session cookie, already used by CSRF) rendered
under the nav after the redirect, hidden in print.

**G3.3 — a submission whose only category files fail validation.** *Observation*: D2 says
"The rest of your export loaded", which would be untrue when nothing loaded. *Letter*: the
record covers "no file recognised" (existing error) but not "recognised, all unreadable".
*Intent*: never claim a load that didn't happen. *Decision*: refused in code with the
existing parse-error form, `Couldn't parse archive: {filename} couldn't be read.` — no new
sentence; surfaced as **Q1**.

**G3.4 — when D4 shows on Home.** *Letter*: "Home line and Help". *Intent*: tell users who
supplied these files that they're kept. *Decision*: Home shows it only when the loaded set
carries a later category; Help always.

**G3.5 — `Export created {date}.`** *Observation*: the links expire on an hours scale.
*Decision*: `{date}` renders through the existing local timestamp filter (date and time),
the house format elsewhere.

**G3.6 — banner line order.** *Decision*: known categories in the established order, then
unknown categories in manifest order.

**G3.7 — later-only sets without a manifest.** *Observation*: e.g. `frames` alone reads
"Loaded 0 of 4 export categories." *Letter*: record §4 — without a manifest the lead counts
against 4. *Decision*: as written; covered by a test.

**G3.8 — when the Windows D13 sentence shows.** *Letter*: "Windows too-old message,
appended sentence". *Decision*: appended only when a candidate was found too old — the
same block also reports "not found", where the pin sentence would mislead.

**G3.9 — the hide control's form.** *Decision*: the theme control's idiom (auto-submit on
change, `noscript` button) with the Session N checkbox-first + hidden-0 pair; the POST is
a display preference and is not refused while inspecting, but the control never renders
there and inspect ignores the cookie.

**G3.10 — the D7 intro's link.** *Decision*: "Upload page" is a link to `/upload`; the text
is byte-identical to D7 with tags stripped (test-pinned that way).

**G3.11 — load-time validation of stored sets.** *Observation*: a stored set was validated
at upload. *Intent*: a later damaged file must not fail startup. *Decision*: the loader
re-validates later categories and skips a failing part with a WARNING (preserve-and-flag;
nothing is shown because the category is not displayed in v1.3.1).
