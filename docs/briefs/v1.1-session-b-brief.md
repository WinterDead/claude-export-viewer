# Claude Export Viewer — v1.1 Session B Brief

Read CLAUDE.md and docs/plan.md before doing anything else.

This session implements the "No Project" sentinel tag. The design below is settled — there are no open design decisions in this brief. If anything in the codebase contradicts these specs, or a spec turns out to be impossible as written, stop and surface it rather than improvising a different design.

## Rationale

Tagging currently has two states: tagged to a project, or untagged. That conflates "not yet reviewed" with "reviewed and deliberately project-less," which breaks the re-import triage workflow — after uploading a new export, there's no way to tell which untagged conversations were already checked.

The new semantics:

- **Untagged** — not yet reviewed. New conversations from a re-import arrive here by default; that default is the triage signal and must not change.
- **No Project** — reviewed, and confirmed to belong to no project.

## B1. Sentinel design

- A single constant in the tagging layer, value `__no_project__`, with the display label **"No Project"** (exact string).
- The sentinel is deliberately **not** a UUID: the synthetic fixtures use all-zero and all-`a` UUIDs, so any reserved-UUID scheme risks collision. A non-UUID string can never collide with a real project UUID or a fixture.
- Stored in the existing `conversation_project` table exactly like any other tag. No schema change, no migration.
- **Verify before implementing:** confirm nothing in the tagging path validates project IDs as UUID-formatted or checks them against the parsed export's project set on write. If such validation exists, stop and surface it — do not silently switch to a different sentinel scheme.

## B2. Where "No Project" appears

- **Per-row dropdown** on the conversations list and the **conversation-detail dropdown**: listed as the first project option, ahead of the real projects, and visually distinct from the clear/no-tag option. Untagging and tagging-to-No-Project are different actions with different meanings — untag returns a conversation to Untagged.
- **Bulk tagging**: available as a target in both "Tag selected to" and "Retag all selected." The existing bulk modes (tag-untagged-only, retag-overwrite, untag) need no behavioural changes — the sentinel is just another target.
- **Conversations-list filter**: a "No Project" filter link alongside the existing Untagged link. Use a readable URL slug (`?tag=no-project`) mapped to the sentinel internally; keep the URL stable once chosen.
- **TagState**: sentinel-tagged rows on live conversations are bucket `live`.

## B3. Where the sentinel must NOT appear

- **`/projects`** never lists it. Home-page stats are derived from the parsed export, so they should be unaffected — verify rather than assume.
- **Orphan-project logic** never applies to it: the sentinel is not subject to project-existence checks, never lands in the orphan-project bucket, never shows the `(Orphan: …)` dropdown treatment, and the orphan purge never deletes sentinel rows on live conversations.
- **No project-detail page.** A request to the sentinel's project-detail URL redirects to the filtered conversations list (`/conversations?tag=no-project`) rather than 404ing.

## B4. Orphan semantics — the one subtlety

The two orphan dimensions split for sentinel rows:

- **Orphan-conversation detection still applies.** If a sentinel-tagged conversation's UUID is absent from the current export, that row belongs in the orphan-conversations bucket like any other — the row is genuinely unreachable. The purge may clear it like any orphan-conversation row.
- **Orphan-project detection never applies.** The sentinel "project" always exists by definition.

A sentinel row must therefore never show a "Project also missing" badge in the orphan-conversations bucket.

## B5. Persistence

Identical to every other tag: keyed on conversation UUID, survives re-imports, no special handling. (This is what makes the triage workflow function — reviewed-as-No-Project status persists while new conversations arrive Untagged.)

## Tests

- Tag a conversation to No Project via the per-row dropdown and via the detail-page dropdown.
- Bulk-tag a selection to No Project; bulk-retag tagged rows to No Project.
- Filters: `?tag=no-project` shows only sentinel-tagged conversations; `?tag=untagged` excludes them; real-project filters exclude them.
- `/projects` does not list the sentinel (verify-negatives: assert absence in the rendered page).
- Home-page project count unchanged by sentinel rows.
- Orphan scan: sentinel rows on live conversations produce no orphans of either kind; a sentinel row whose conversation is missing lands in orphan-conversations without a "Project also missing" badge; purge clears it.
- Sentinel project-detail URL redirects to the filtered conversations list.
- Persistence: sentinel tag survives a simulated re-import (existing re-import test pattern).
