## Gate vocabulary

- **Soft gate** — resolve it if the fix is obvious and within the design's intent, and flag
  it prominently in the report.
- **Hard stop** — end the session and report without implementing, even if the resolution
  seems obvious.

**Hard stops for this session**: any finding whose fix would change a design decision, a
default, the sanitiser/stack, or user-facing copy beyond Task B's specified edits; any
personal-reference finding in committed files (report the exact location; the fix may need
operator judgment about what replaces it).

## Task A — audit items

1. **Export write paths, fresh eyes**: re-verify — as an auditor, not by rerunning the
   tests — that no export or print code path writes server-side (including temp files of our
   own making), that the thinking default is off at every surface (serializer, both
   endpoints, both UI controls), and that bulk output corresponds exactly to the posted
   selection. Confirm the existing no-trace snapshot tests genuinely cover the on-disk state
   the app can write.
2. **The Werkzeug spool item** (Session K's recorded audit input): document the actual
   behaviour — multipart uploads over the spool threshold go to an OS temp file during
   request parsing and are deleted at request end — and verify the deletion claim against
   the installed Werkzeug's code. Verdict to state: whether the help page's "nothing saved
   to disk" claim remains fair under an ordinary reading. This is documentation of a
   stack-inherent behaviour, not something to fix.
3. **Log-content audit**: review every logging call the app can emit at runtime and confirm
   none can carry conversation content, titles, or real identifiers — sources, types, and
   counts only. The startup-fallthrough WARNING and parser preserve-and-flag WARNINGs are
   the obvious candidates; check them all.
4. **Security-pin re-check**: confirm the host-binding canary and secret-key tests still
   express the intended guarantees (read them, don't just note they pass), and that no
   v1.2 code introduced a new network listener, redirect target, or request-driven file
   path.
5. **Dependency advisories**: run a vulnerability audit (e.g. `pip-audit` in a scratch
   venv — a dev tool, not a new dependency) against the four pinned ranges at their
   currently resolving versions; report findings with severity. Version bumps within the
   existing caps are a soft gate; anything needing a cap change is a hard stop.
6. **Final public-trajectory sweep, whole tree**: every committed file — code, docs,
   briefs, reports, fixtures, `.claude/`, configuration — checked against the
   public-trajectory rule (no personal paths, no machine names, no usernames beyond the
   public handle, no real export data). Grep for the obvious patterns, then eyeball the
   hits *and* the docs/briefs directory contents as a human reader would; the reports
   contain prose that greps don't parse.
7. **Screenshot currency check** (report only — screenshots are public voice and belong to
   the close session): compare the four README screenshots against the current UI and list
   every visible divergence (new Inspect nav item, changed action bar, new detail-page
   controls, anything else). State whether each screenshot is merely stale or now
   misleading.

## Task B — operator pass findings (v1.2.0 browser pass, 2026-07)

B1. **Nav order**: reorder the top bar so History sits directly right of Upload —
Home … Upload, History, Inspect, Help. History records uploads; Inspect between them is
counterintuitive. Verify no test pins the old order; adjust any that does.

B2. **Export-control grouping**: wrap the two checkboxes together with the **Export** and
**Copy conversation** buttons in one visually grouped control (fieldset or equivalent),
legend byte-exact: **Export options**. Print / Save as PDF sits *outside* the group — it is
screen-WYSIWYG and the toggles don't apply to it. First **verify** whether Copy currently
honours the checkbox states — the operator has confirmed it currently **doesn't** (quite
possibly the same root cause as B3; determine whether it is). Fix it so it does — the
group's visual promise must be true. Covered by B3's end-to-end tests.

B3. **The dead attachment toggle (bug)**: the operator observed that Include attachment
text has no effect — attachments export as reference-only regardless. Reproduce **through
the real rendered form**, not hand-built parameters. First hypothesis to check: the
checkbox+hidden-0 pairs submit duplicate query parameters and the server reads the *first*
(the hidden 0), so a ticked box never registers — which would also silently disable
Include thinking blocks via the form (test that explicitly, whatever the cause turns out to
be). Fix (read the last value, or restructure the pair mechanism), and add end-to-end tests
that submit the template's actual form markup for all four checkbox states on both the
Export and Copy paths. The meta-gap this bug exposes: the existing endpoint tests built
their parameters by hand and never exercised the form — the new tests close that class.

B4. **Summary consistency (operator-raised; resolution below is chat-ratified)**: the
conversation summary prints (it's on the page — WYSIWYG) but never appears in Export or
Copy. Resolution — no toggle: add `summary` to the frontmatter, only when the conversation
has one, using a YAML-safe form for multi-line text. Export then carries it as metadata,
Copy (frontmatter off) omits it — matching the operator's copy intuition — and Print keeps
showing it. Body-level control, if lived use wants it, is 1.2.6+ territory — record that
explicitly by adding the summary-placement toggle to `docs/plan.md`'s 1.2.6+ queued list,
alongside the print-timestamp and link-appendix toggles, so it isn't lost between work
windows. Amend
`docs/export-design.md`'s frontmatter block: insert directly after the `title` line,
byte-exact:

<!-- VERBATIM -->
summary: "<conversation summary>"     # only when the conversation has one
<!-- END VERBATIM -->

And in help.md's "Exporting conversations" intro, replace the parenthetical
`(title, dates, message count, your project tag if you've set one)` with, byte-exact:

<!-- VERBATIM -->
(title, dates, summary, message count, your project tag if you've set one)
<!-- END VERBATIM -->

Tests: field present only when a summary exists; a multi-line summary round-trips as valid
YAML.

B5. **The links appendix doesn't appear (bug)**: the operator confirms no inline `[N]`
markers and no Links section **anywhere — neither in real print preview nor in an actual
printed PDF** — on link-bearing conversations, despite Session N's driven-browser pass
reporting confirmation. Reproduce
in a real print preview against a link-bearing fixture, and **reconcile what N's pass
actually measured versus the `@media print` reveal** — candidate causes: the appendix and
markers are built but the print CSS never un-hides them (a class-name mismatch between the
JS and the CSS is the likely seam), the script isn't loaded on the template, the
`beforeprint` wiring, or the selector scope. Fix, pin with content guards that tie the JS's
generated class names to the print CSS that reveals them, and state the root cause
explicitly in the report — including what the N pass's "confirmation" actually checked.
