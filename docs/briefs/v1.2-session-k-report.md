## Prominent flag — the one boundary of "no disk artifacts whatsoever"

Werkzeug (Flask's HTTP layer) spools any multipart upload body larger than ~500 KB to an
OS-managed temporary file while parsing the request, before application code runs. This is
pre-existing behaviour of **every** upload route (the Upload page has always had it), it is
outside `cache/` and outside the app's control short of replacing the form parser — which
would be a stack change, itself a hard stop — and the spool file is deleted automatically
when request handling ends, so no artifact remains after the request. Every guarantee the
no-trace rule enumerates holds and is test-pinned: nothing under `cache/`, no parse pickle,
no `upload_history` row, in-memory search index. Judged report-flag material rather than a
hard stop because the hard stop targets writes *originating from inspect mode's
implementation*; this one originates below the application for all uploads alike, and the
fixture-sized files in the test suite never even reach the spool threshold. Recorded as a
v1.2.5 audit input.

## Design notes (within the brief's intent)

- **Primary stays resident.** The brief left residency to Code: the primary `Export` is
  never unloaded — inspect state lives beside it and "Return to my export" just discards
  the state. Faster and simpler than re-running the load path, and an app restart
  trivially lands on the primary because inspect state is process memory.
- **Tag surfaces pin to the primary.** The orphan-banner count and `/orphans` resolve tags
  against the primary export even while inspecting; resolving them against an inspected
  archive would mark every tag orphaned. The purge form is replaced by a short notice in
  inspect mode (the POST refuses regardless). Project tag counts and the project-detail
  "Tagged conversations" section are hidden while inspecting for the same reason — they
  pair primary tag rows with inspected entities.
- **Re-inspect replaces.** POSTing a new file while already inspecting swaps the inspected
  view (closing the previous in-memory index); a corrupt file in that state leaves the
  previous inspection loaded, mirroring the untouched-view rule.
- **Concurrency accepted, as briefed.** Inspect state is app-global on a single-process
  dev server, so concurrent tabs share it; the in-memory SQLite connection is created with
  `check_same_thread=False` because the threaded dev server serves later pages from other
  threads — access after the index build is read-only.

## Soft gates resolved (flagged per the brief)

1. **Parse-error copy** (mechanical, per the brief) — the Inspect page reuses the upload
   flow's shape: "No file selected." / "File must be a .zip." / "Couldn't parse archive:
   {details}", rendered in the same `.warn` style on the Inspect page itself.
2. **Help link** (mechanical, per the brief) — "Inspect page" links to `/inspect` via
   `[Inspect page](/inspect)`, matching the `[History](/history)` idiom.
3. **Help copy reflow** — help.md renders single newlines as `<br>` (nl2br), and every
   existing section is one line per paragraph. The authored section's soft line wraps
   would have rendered as forced breaks no other section has, so the paragraph was
   reflowed onto one line: wording and punctuation byte-exact, wraps replaced by single
   spaces. Same classification as Session I/J's VERBATIM line-structure determinations
   (HTML context — wraps collapse; the line shape is not the rendering).
4. **Upload-page notice copy** — not authored in the brief, so written in-session:
   "Uploading is disabled while you're inspecting an export — Upload replaces your stored
   export, and inspecting never touches it. Use **Return to my export** in the banner
   first."
