# v1.3.0 operator hand-test brief — real-export upload flow

Committed deliverable of Session S Phase 4. This is the procedure that clears the
*provisional* markers on the upload shape (design record §4/§5): the multi-file picker,
subset loading, the degraded-view banner, set storage, and the cap knob, exercised against
the real export set — plus the one help claim code cannot verify (the export request path
in the Claude UI). Report findings in the format at the end; the plan's provisional
markers stay until this brief's results are recorded.

Throughout: "the real set" means the four category zips plus the manifest in
`data/export-2026-08/`. All steps run on your own machine; nothing here sends data
anywhere.

> **Corrected 2026-09-01 (Session T), from the hand-test report:** step 1.3 now moves
> `data\` aside — the startup order falls back to the `data\data.zip` dev copy before the
> built-in sample, which the original reset omitted (scenario 1 deviation). The §2.6 and
> §6.5 History expectations now describe the When column's actual relative-time behaviour
> (scenario 2 deviation).

## 0. Freshness gate (run before anything else)

1. From the project root:

   ```
   git pull
   git log --oneline -5
   ```

   **Expect**: the log includes `v1.3.0 Session S Phase 4` (or later). If not, stop —
   you're testing stale code.
2. Run the suite:

   ```
   .venv\Scripts\python.exe -m pytest -q
   ```

   **Expect**: all tests pass, zero failures. A red suite is a hard stop.

## 1. Backup and reset procedure

Fresh state for this test means no active export and no parse cache — tags are precious,
so the database is backed up, not deleted.

1. Stop the app if it's running.
2. Back up your tags: copy `cache\viewer.sqlite` somewhere safe.
3. Delete, if present: `cache\active_export\` (the whole folder),
   `cache\active_export.zip`, and `cache\parsed_export.pkl`. Then move the contents of
   `data\` out of the project folder for the duration of the test — the app falls back to
   `data\` before the built-in sample — and move them back afterwards. Move, don't
   delete: the real export set is what the aggregate tests need.
4. **To restore after testing**: stop the app, copy your preferred export files back in
   (or re-upload via the UI), and put the backed-up `viewer.sqlite` back if anything
   happened to it. Tags were never at risk from uploads themselves — the backup is belt
   and braces.

Start the app for each numbered scenario with `run.ps1` (or
`.venv\Scripts\flask --app app run`) and stop it between scenarios where the step says
so.

## 2. Full set, manifest included

1. Start the app. **Expect**: sample data (footer names the synthetic fixture), no
   banners.
2. Open **Upload**. **Expect**: one file input that accepts multiple files, hint text
   naming `.zip` archives plus the optional manifest `.json` and a 200 MB per-file cap.
3. Select all five files from `data\export-2026-08\` (four zips + the manifest) in one
   pick and upload.
4. **Expect**: redirect to Home; your real counts on the stats panel (259 conversations,
   2,970 messages, 7 projects, 3 project memories); **no** degraded banner; footer lists
   the set's file paths.
5. Check `cache\active_export\`. **Expect**: exactly the five files you supplied, with
   their original names.
6. Open **History**. **Expect**: a new row reading
   `5 files: conversations, projects, memories, light_metadata, manifest` with a
   fingerprint; the When column shows a relative time (`just now` at first, coarsening
   through minutes, hours, and days — it never switches to an absolute date; hover the
   value for the absolute local timestamp).
7. Restart the app. **Expect**: your export loads (not sample data), no new History row.

## 3. Memory page (full set still loaded)

1. Open **Memory**. **Expect**: three group headings — `Conversation memory`,
   `Memory files` (18), `Project memories` — in that order.
2. **Expect** under Memory files: your files grouped by folder (`/areas/`, `/topics/`,
   plus root-level `profile.md` and `preferences.md`), each collapsed under its full
   path with an `Updated {date}` line in your local time.
3. Expand a file that has a `---` header. **Expect**: the header shown verbatim in a
   bordered preformatted block, the body rendered as formatted text below it.
4. Search for a phrase you know is in a memory file. **Expect**: a Memory hit titled by
   the file's path; clicking it opens the Memory page with that file expanded.

## 4. Account page (full set still loaded)

1. **Expect**: an **Account** entry in the nav (between Memory and Search).
2. Open it. **Expect**: your name, email, and account UUID under `Account`; under
   `Login history`, a 12-row table, newest first, with columns `Timestamp`, `Method`,
   `IP address`, `Location`, `Browser & OS`; timestamps in your local time.
3. Sanity-check a couple of rows against logins you recognise (method, rough dates,
   browser).

## 5. Conversation rendering spot-checks (full set still loaded)

1. Open a conversation you know used web search. **Expect**: a `Sources` list beneath
   cited paragraphs; tool cards showing display bodies (tables as tables, links as
   links, code as highlighted code); collapsed `json_block`/`rich_content` sections
   that expand to formatted JSON.
2. Open a recent conversation with visible thinking. **Expect**: collapsed thinking
   blocks teased by their first summary; expanding shows the full summary list above
   the reasoning; any block Claude hid in the app carries a small
   `Hidden in the app` badge with a tooltip.
3. If you know a conversation with an injected prompt (skill/feature preamble),
   **expect** a collapsed `Injected prompt` card that expands to the prompt text.

## 6. Subsets and the degraded banner

For each subset below: stop the app, run the reset (step 1.3 only — leave the sqlite
backup alone), start, upload the listed files, and check.

1. **Conversations only** (`conversations-000.zip`): banner reads
   `Loaded 1 of 4 export categories.` with three missing-category lines (projects,
   memories, account — conversations' line absent); browsing and search work; Memory
   page shows the empty state; no Account entry in the nav.
2. **Conversations + manifest**: same banner plus
   `The manifest lists 4 files; 1 were supplied.`
3. **Everything except light_metadata** (three zips, no manifest): banner reads
   `Loaded 3 of 4 export categories.` with only the account line; Memory page full; no
   Account nav entry.
4. **Manifest alone**: upload is rejected with a message that the manifest alone
   doesn't contain your data; the previously loaded export is untouched.
5. **Full set again, manifest omitted** (four zips): no banner; History row reads
   `4 files: conversations, projects, memories, light_metadata` (When column relative,
   as in §2.6).

## 7. Inspect-mode set

With the full set loaded as your active export:

1. Open **Inspect**, select `conversations-000.zip` + `projects-000.zip` (a subset),
   and inspect.
2. **Expect**: the blue inspect banner reading
   `Inspecting 2 files: conversations, projects — read-only.` plus the grey degraded
   banner for the inspected view; your conversations browse read-only; no tagging UI.
3. **Expect**: `cache\active_export\` untouched (same five files), no new History row.
4. Click **Return to my export**. **Expect**: full view back, banners gone.

## 8. Cap knob override

1. Stop the app. In the same terminal:

   ```
   $env:VIEWER_MAX_UPLOAD_MB = "10"
   .venv\Scripts\flask --app app run
   ```

2. Open **Upload**. **Expect**: the hint now says `10 MB per file`.
3. Upload `conversations-000.zip` (38 MB). **Expect**: rejected, naming the file and
   the 10 MB per-file cap; previous export untouched.
4. Stop the app, clear the override (`Remove-Item Env:VIEWER_MAX_UPLOAD_MB`), restart,
   and re-upload the full set to leave the app in its normal state.

## 9. Export request path in the Claude UI

The one help claim code cannot verify. In Claude (claude.ai or the desktop app):

1. Click your initials in the lower-left corner → **Settings** → **Privacy** →
   **Export data**.
2. **Expect**: each step exists under exactly those names. If any label or location has
   moved, note the actual path — README "Getting your export" and help "Getting your
   export from Anthropic" both cite it.

There's no need to complete a new export request unless you want a fresh set.
