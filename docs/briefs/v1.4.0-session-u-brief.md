# Session U Brief — v1.3.1 and v1.4.0

**Read first**: `CLAUDE.md`, `docs/plan.md`, then **`docs/export-categories-design.md`**
(normative for everything in this session) and `docs/format-support-design.md` (which it
amends). This brief adds mechanics, gates, and order only; where the two disagree, the
record wins and the disagreement is a finding.

**Arc**: one long session, nine phases, two versions. Phases 0–3 deliver v1.3.1; phases
4–6 deliver v1.4.0; phase 7 is extra work; phase 8 is the operator's review and the
release. **There are no open design decisions in this brief** — every product and
security decision is in the record. Questions the record does not answer are refused in
code and surfaced, never guessed (see Gates).

## Gates

- **Soft gate** — resolve it when the fix is obvious and within the record's intent, and
  disclose it in the phase report in the four-part shape: *observation, letter, intent,
  decision*. Use for premise mismatches with one defensible resolution, mechanical
  adaptations, counts that differ from the verification table, and naming conventions
  already established in the code.
- **Hard stop** — end the phase, report, and wait, even when the resolution seems obvious.
  The hard stops for this session are listed at the end. Everything else is a soft gate.

Any phase boundary is a legitimate place to end the session; unfinished phases run later
under this same brief.

## Ground rules

- **Branch**: all work happens on branch `session-u`, created from `main` at `v1.3.0`.
  Every phase closes with the full CLAUDE.md checklist and **pushes `session-u`** to
  origin. `main` is not touched until phase 8, after the operator's review. No tags until
  phase 8.
- **Commits**: authored as WinterDead with the noreply address; **no `Co-Authored-By`,
  `Claude-Session`, or "Generated with" trailers**, whatever the harness suggests — the
  operator's instruction, now in CLAUDE.md (phase 0).
- **Real data**: the operator's real exports are at the directory named by the
  environment variable `VIEWER_REAL_EXPORT_DIR` (given in the opening prompt, outside the
  repo). You may run **only** the committed scanner and the real-data skip tests against
  it. Never open, print, copy, or quote its content; every emitted value is a count, a
  type name, a key name, a length statistic, or an allowlisted enum that passes the
  cardinality cap. Nothing derived from it enters a commit except the phase 1
  confirm/diverge table, which is aggregate by construction. Any phase that ran real data
  runs CLAUDE.md step 5 before its commit.
- **Fixtures**: synthetic from scratch, behaviourally parallel to the observed structures
  (verification table §2 of the record), RFC 5737 addresses, RFC 2606 domains,
  `example.invalid` URLs, neutral relative paths. No real title, name, prompt, site name,
  or path, ever.
- **Copy**: user-facing strings come verbatim from the record's appendix and this brief's
  appendix. Drafting latitude only for new Help sections and README feature bullets, in
  the established voice; list every drafted passage in the phase report. Every behavioural
  claim in user-facing text is checked against the code before commit.
- **Tests verify the rendered artifact**: every UI-bearing behaviour gets at least one
  test that submits or reads the template's real markup. Browser passes name the layer
  they measured. "No browser pass" is a valid disclosed state when the reason is
  structural, assigned to the operator hand-test.
- **House rules**: preserve and flag; sanitiser allowlist unchanged; full-text search
  (FTS) row-count
  invariant moves only in lockstep with its kinds; every new writable global is patched
  by the shared `app_factory` in the same commit; `git status` and a glance at `cache/`
  after any test run that touches storage.
- **Independent reads**: where this brief asks for a stranger read or a review, use a
  fresh subagent given only the files, not your conclusions, so the work isn't grading
  itself. Subagents never receive the real-export path.
- `.claude/settings.local.json` is untracked and stays untracked.

## Phase 2 — v1.3.1 ratified items

### 2.1 Tool-result display bodies collapse by size (amendment A5)

- Constants in one place (`viewer/render.py`, named): `DISPLAY_BODY_COLLAPSE_LINES = 30`,
  `DISPLAY_BODY_COLLAPSE_CHARS = 2000`. A display-content body whose rendered source
  exceeds *either* threshold renders **pre-collapsed** on the shared `collapsible`
  contract Session T established; shorter bodies render open. Applies to every
  display-content type that renders a body (`text`, `code_block`, `table`, and any future
  type that isn't already always-collapsed); `json_block` and `rich_content` keep their
  always-collapsed fallback. The same rule governs the Artifacts page's View source in
  phase 5.
- Teaser (appendix U1): the tool block's own `message` line when present, else the tool
  name, followed by the line count.
- Tests in `test_block_rendering.py`: under both thresholds renders open; over the line
  threshold only, over the character threshold only, and over both, all render collapsed
  with the U1 teaser; the collapsed card uses the shared contract's classes and
  attributes; `json_block`/`rich_content` unchanged. The `current/` fixture gains one
  document-sized synthetic `text` body.
- Append U2 verbatim to `docs/briefs/v1.3.0-session-s-operator-hand-test-report.md` under
  a new heading `Addendum (2026-10)`. The operator's original text is not edited.
- Apply A5 (appendix U3) to `docs/format-support-design.md` verbatim.

### 2.2 The real export leaves the tree

- The real-data skip tests (`test_parser.py`'s legacy aggregate test and
  `test_parser_current.py`'s current twin) read `VIEWER_REAL_EXPORT_DIR`: unset or
  missing → skip, with the reason naming the variable. The directory may hold several
  exports (legacy ZIPs at its root; sets in immediate subdirectories); each recognised
  export is a parametrised case. Hard-coded `data/…` paths are removed.
- **The real-data assertions become invariants, not counts** (counts are specific to one
  export and go stale): the export parses with no exception; no `UnknownBlock` whose type
  the parser now knows; every conversation's parent graph resolves; the FTS row-count
  invariant holds on the indexed export; for v1.4.0 categories (added in phase 4): every
  `active_version` resolves, every multi-file version's integrity check passes, every
  run's task resolves or is preserved as an orphan. Failures print aggregate counts only.
- The startup load order loses the `data/` step: uploaded set → built-in fixture. The
  dev-copy code path and its tests go; the fall-through-with-banner behaviour for a corrupt
  stored set is unchanged. Tests: the fixture loads when no set is stored; env-var
  handling (set, unset, missing directory, a directory with several exports).
- Docs: CLAUDE.md's tree drops the `data/` line and updates the `app.py` comment; README's
  Development section and Help's Backups section lose any `data/` mention (verify — they
  may already be clean); `docs/export-schema.md` and the scanner docstring switch to a
  neutral example path. `.gitignore` keeps `data/`. Record the retirement in the plan
  with the rationale *real exports never live in the tree*.
- Close phase 2.

## Hard stops

- A red suite at any phase close, or a dirty baseline.
- Any sanitiser-allowlist change.
- Any FTS invariant drift not moved in lockstep.
- A verification-table divergence that contradicts a record decision.
- Any record §6.3 outcome that cannot be met, or any temptation to let artifact scripts
  run.
- Anything that would fetch a URL at runtime, or render something that could.
- Anything touching the GitHub account, repo settings, or Releases.
- A real-data output containing anything other than aggregates — stop, discard, fix the
  tool, report (privacy procedures' mess-up order).
