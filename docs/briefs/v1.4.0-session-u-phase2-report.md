## Disclosures (four-part)

**G2.1 — U1 pluralisation.**
*Observation*: a body over 2,000 characters on a single line would read "(1 lines)".
*Letter*: `{message or tool name} ({N} lines)`.
*Intent*: a correct line count beside the teaser.
*Decision*: "line" is singular when N is 1 (the C2 precedent for pluralised copy); every
other N renders the U1 string exactly.

**G2.2 — the teaser's message line was not in the model.**
*Observation*: the parser dropped the tool block's `message` field.
*Letter*: "the tool block's own `message` line when present, else the tool name".
*Intent*: the teaser reads as the product's own status line.
*Decision*: `message` added to `ToolUseBlock` and `ToolResultBlock` (non-empty strings only);
the parse cache invalidates by parser-module hash as designed.

**G2.3 — what "rendered source" measures.**
*Observation*: the brief counts lines and characters of the "rendered source".
*Letter*: thresholds apply to the body's rendered source.
*Intent*: measure what the user would scroll through.
*Decision*: `text` → its text; `code_block` → its code; `table` → one line per row, cells
tab-joined; `rich_link` → title and URL (a sized type, never realistically folded).

**G2.4 — the fold's class name.**
*Observation*: no established class for a size fold.
*Letter*: "the shared `collapsible` contract's classes and attributes".
*Intent*: one mechanism, not a parallel one.
*Decision*: `collapsible display-content-fold` — on the contract, skinned by nothing new.

**G2.5 — real current sets red until phase 3.**
*Observation*: with the variable set, both real sets fail on v1.3.0 code.
*Letter*: "the export parses with no exception".
*Intent*: the invariant tests prove the real exports load.
*Decision*: reported as observed; they are the v1.3.1 regression itself and turn green in
phase 3. The phase-close gate is the ordinary suite, which is green.

**G2.6 — what "the parent graph resolves" means.**
*Letter*: "every conversation's parent graph resolves".
*Intent*: no message is lost to an orphan parent or a cycle.
*Decision*: no message names a parent missing from its conversation, and every message is
reachable from a root. The helper is tested to count both failure kinds on the synthetic
bad fixtures.

**G2.7 — keeping failure output aggregate.**
*Observation*: a `pytest.fail` inside an `except` block printed the chained exception's
message during the first real run (it named only category ZIP filenames, but other
messages can name identifiers); parser warnings, which name UUIDs, are shown in captured
logs on failure.
*Letter*: "Failures print aggregate counts only."
*Intent*: no identifier ever reaches test output.
*Decision*: failures are raised outside the `except` (no chaining) and name only the
exception type; the real-data tests silence the `viewer` loggers instead of capturing them.

**G2.8 — the pre-set ZIP stays in the load order.**
*Letter*: "uploaded set → built-in fixture".
*Intent*: drop the `data/` step only.
*Decision*: `cache/active_export.zip` (a stored upload from before v1.3.0) is still an
uploaded export and keeps its tolerance step.

**G2.9 — importing `app` ran the real startup against `cache/`.**
*Observation*: the house-rule glance at `cache/` after this phase's test runs found
`parsed_export.pkl` and `viewer.sqlite` rewritten. Cause: `app.py` ended with a module-level
`app = create_app()`, so every `import app` (the suite does it in many modules) ran the
default load order — parsing the operator's stored export under `cache/active_export/`,
rebuilding its search index, and rewriting the pickle whenever the parser changed.
Pre-existing since v1.0; tags were never touched.
*Letter*: "`git status` and a glance at `cache/` after any test run that touches storage";
real data is touched only by the scanner and the real-data tests.
*Intent*: ordinary test runs never read or write the operator's stored data.
*Decision*: the module-level instance is removed; `flask --app app run` (the launchers and
`.claude/launch.json`) finds the `create_app` factory by Flask's documented discovery and
calls it with no arguments, so serving is unchanged (verified with `flask --app app
routes`). Pinned by `test_importing_app_builds_no_app`. A full suite run now leaves both
files' modification times unchanged. While diagnosing this, a directory listing of the
stored set printed its file names into the session's tool output (one carries an export
job identifier); nothing was written anywhere, and later checks look at timestamps only.
